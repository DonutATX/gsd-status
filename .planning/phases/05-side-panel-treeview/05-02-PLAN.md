## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `GsdState` snapshot → tree node construction | Parsed `.planning/` content flows into TreeItem labels/commands rendered by VS Code |
| `TreeItem.command.arguments` → command handler | `phase.headerLine` (a number from parsed ROADMAP.md) is passed to `gsd.openRoadmap` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03 | Tampering | Phase/entry text rendered as TreeItem labels | accept | Labels are plain strings; VS Code TreeView renders them as text, no markdown/HTML execution path. Read-only display, local file, low value. |
| T-05-04 | Elevation of Privilege | `headerLine` passed via `command.arguments` to `gsd.openRoadmap` | mitigate | Provider passes `phase.headerLine` unchanged; the `gsd.openRoadmap` handler (plan 03 / existing) must validate it is a non-negative integer before `revealLine` (RESEARCH.md Security Domain note). Documented as a plan-03 acceptance criterion. |
| T-05-05 | Denial of Service | `getChildren` slicing `recentEntries` by `_recentCount` | accept | `_recentCount` is bounded by the `gsd.recentActivityCount` setting (min 1); slice is O(N) with small N. No unbounded recursion — tree depth is fixed at 3. |
| T-05-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages this plan/phase (RESEARCH.md Package Legitimacy Audit confirms). No install task; nothing to verify. |
</threat_model>
