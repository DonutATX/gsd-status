# Phase 5 — UI Design Contract

> Visual and interaction contract for the Side Panel TreeView phase.
> Generated by gsd-ui-researcher. This is a VS Code extension phase —
> there is no web UI, no CSS, and no custom design system. VS Code's
> native theme governs all color, spacing, and typography. Contracts
> below describe the VS Code contribution surface, not a web component library.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (VS Code native theme) |
| Preset | not applicable |
| Component library | VS Code TreeView API (`vscode.TreeDataProvider<T>`, `vscode.TreeItem`) |
| Icon library | Codicons (`ThemeIcon` — built in to VS Code) |
| Font | VS Code editor font (user-controlled, not set by extension) |

Source: CONTEXT.md `<specifics>` — "Standard VS Code Extension API patterns. No third-party tree libraries."

---

## Spacing Scale

VS Code's native TreeView renders all spacing. The extension does not set padding, margins,
or gap values. All layout is delegated to the host theme.

| Token | Value | Usage |
|-------|-------|-------|
| (not applicable) | VS Code native | TreeView item indentation, row height, icon gap |

Exceptions: The Activity Bar SVG icon is 24×24px per VS Code icon guidelines — this is a
fixed asset dimension, not a spacing token.

---

## Typography

VS Code's native TreeView renders all text. The extension sets node `label` and `description`
strings only — font size, weight, and line height are controlled by the host theme.

| Role | Value |
|------|-------|
| Node label | String assigned to `TreeItem.label` — VS Code renders at theme body size |
| Node description | String assigned to `TreeItem.description` — VS Code renders as muted secondary text |
| Tooltip | String or `MarkdownString` assigned to `TreeItem.tooltip` |

No custom font sizes or weights are set by this extension.

---

## Color

All color is delegated to VS Code's active theme. The extension does not set hex values,
CSS variables, or theme color contributions.

| Role | How Applied |
|------|-------------|
| Active phase distinction | `ThemeIcon` codicon `$(play)` — VS Code colors it using `list.activeSelectionIconForeground` |
| Done phase | `ThemeIcon` codicon `$(pass-filled)` — VS Code colors it using standard icon foreground |
| Pending phase | `ThemeIcon` codicon `$(circle-outline)` — VS Code colors it using standard icon foreground |
| Activity Bar icon | Monochrome SVG using `currentColor` — inherits Activity Bar icon foreground from active theme |
| Welcome view text | Rendered by VS Code `viewsWelcome` — inherits editor foreground |

Source: CONTEXT.md `<decisions>` — "Phase node icons are state-specific `ThemeIcon`s."

## Tree Node Hierarchy

### Top-Level Structure

```
[Activity Bar] GSD icon
  └── GSD Panel (view id: gsd.treeView)
        ├── Recent Activity              ← always first top-level node
        │     ├── [entry 1]              ← STATE.md entry (last N, driven by gsd.recentActivityCount)
        │     ├── [entry 2]
        │     └── ... (up to N entries, default 5)
        ├── Phase 1: Scaffold + ...      ← phase node (done)
        ├── Phase 2: Parsers + Tests     ← phase node (done)
        ├── Phase 3: StateController...  ← phase node (done)
        ├── Phase 4: Tooltip, Commands   ← phase node (done)
        ├── Phase 5: Side Panel TreeView ← phase node (ACTIVE — expanded by default)
        │     ├── Goal: [goal text]      ← single goal child
        │     ├── [criterion 1]          ← one child per success criterion
        │     ├── [criterion 2]
        │     └── ...
        └── Phase 6: Packaging          ← phase node (pending)
```

Source: CONTEXT.md `<decisions>` — tree structure section.

### Collapsible State Contract

| Node Type | Default State | Can User Collapse? |
|-----------|---------------|-------------------|
| "Recent Activity" section | Expanded | Yes |
| Active phase node | Expanded | Yes |
| Done phase nodes | Collapsed | Yes |
| Pending phase nodes | Collapsed | Yes |
| Goal child item | Leaf (no children) | No |
| Success criterion child item | Leaf (no children) | No |
| Recent Activity entry | Leaf (no children) | No |

Source: CONTEXT.md `<decisions>` — "Default collapse state: the active phase node is expanded; all other phase nodes are collapsed."

## Interaction Contract

### Click Behaviors

| Node Type | On Click Action |
|-----------|----------------|
| Phase node | Open `.planning/ROADMAP.md` at `RoadmapPhase.headerLine` via `vscode.window.showTextDocument` + `revealLine` |
| Recent Activity entry | Open `.planning/STATE.md` via `vscode.window.showTextDocument` |
| Goal child item | No command (informational leaf) |
| Success criterion child item | No command (informational leaf) |
| "Recent Activity" section header | No command (section header) |

Source: CONTEXT.md `<decisions>` — "Clicking a phase node opens `.planning/ROADMAP.md` at that phase's header line" and "Clicking a 'Recent Activity' entry opens `.planning/STATE.md`."

### Toolbar Action

| Action | Icon | Command ID | Placement |
|--------|------|------------|-----------|
| Refresh | `$(refresh)` | `gsd.refreshTree` | `view/title` menu for `gsd.treeView` |

The toolbar refresh button triggers `StateController.refresh()`. Tree subscribes to `onStateChanged` and fires `onDidChangeTreeData(undefined)` using stable element identities to preserve expansion state.

Source: CONTEXT.md `<decisions>` — PANL-07 stable identity behavior.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Welcome view message (exact) | `No GSD project found. Run /gsd:new-project to initialize.` |
| Recent Activity section label | `Recent Activity` |
| Goal child label prefix | `Goal: ` + goal text from ROADMAP.md |
| Success criterion label | Criterion text verbatim from ROADMAP.md |
| Toolbar refresh tooltip | `Refresh GSD tree` |
| View container title | `GSD` |
| View title | `GSD Workflow` |
| No recent entries label | `No recent activity` (shown as single leaf under Recent Activity when STATE.md has no entries) |
| Error state label | `Error reading GSD files` (shown as single leaf when `GsdState` is `error`) |

Source: REQUIREMENTS.md PANL-05 (welcome copy), CONTEXT.md decisions section (exact welcome message). All other copy derived from phase goal and standard VS Code conventions.

### Copywriting Rules

- Phase node labels use the phase name verbatim from ROADMAP.md (e.g. `Phase 5: Side Panel TreeView`).
- Do not abbreviate or truncate phase names in tree labels.
- Recent Activity entry labels use the STATE.md entry text verbatim; timestamp shown in `TreeItem.description`.
- No punctuation added to criterion text — display as parsed.

## Package.json Contributions Contract

The following `contributes` entries are required in `package.json`:

```jsonc
"contributes": {
  "viewsContainers": {
    "activitybar": [
      {
        "id": "gsd",
        "title": "GSD",
        "icon": "resources/gsd-icon.svg"
      }
    ]
  },
  "views": {
    "gsd": [
      {
        "id": "gsd.treeView",
        "name": "GSD Workflow"
      }
    ]
  },
  "viewsWelcome": [
    {
      "view": "gsd.treeView",
      "contents": "No GSD project found. Run `/gsd:new-project` to initialize.",
      "when": "!gsd.hasProject"
    }
  ],
  "commands": [
    {
      "command": "gsd.refreshTree",
      "title": "Refresh GSD tree",
      "icon": "$(refresh)",
      "category": "GSD"
    }
  ],
  "menus": {
    "view/title": [
      {
        "command": "gsd.refreshTree",
        "when": "view == gsd.treeView",
        "group": "navigation"
      }
    ]
  }
}
```
