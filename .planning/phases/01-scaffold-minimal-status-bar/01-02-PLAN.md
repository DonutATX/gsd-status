    Write `src/extension.ts` (single file, ≤80 lines total including the ≤40-line parseLite helper):

    Imports: `vscode` (default style `import * as vscode from 'vscode'`), `node:fs/promises` as `fs`, `node:path` as `path`.

    Export `activate(context: vscode.ExtensionContext): void`:
    - Create a StatusBarItem with `vscode.window.createStatusBarItem(vscode.StatusBarAlignment.Left, 100)`.
    - Push it to `context.subscriptions` immediately (SCAF-04).
    - Call `item.show()` (RESEARCH anti-pattern: items are hidden by default).
    - Set `item.text = 'GSD: No project'` synchronously as the default so the bar is never empty.
    - Fire-and-forget `void updateStatusBar(item)` so activate() returns immediately (RESEARCH Anti-Pattern: never block activate()). Do NOT mark activate() async.
    - Do NOT set `item.command` or `item.tooltip` (locked decisions; those land in Phase 4).

    Export `deactivate(): void` as a no-op (context.subscriptions handles disposal).

    Implement `async function updateStatusBar(item: vscode.StatusBarItem): Promise<void>`:
    - `const folder = vscode.workspace.workspaceFolders?.[0]` (WSP-01, RESEARCH Pitfall 2).
    - If `!folder`: leave `item.text = 'GSD: No project'` and return.
    - Build `roadmapPath = path.join(folder.uri.fsPath, '.planning', 'ROADMAP.md')`.
    - Wrap `fs.readFile(roadmapPath, 'utf8')` in try/catch — on failure (ENOENT or any read error) set `item.text = 'GSD: No project'` and return (STAT-02 / WSP-01: missing .planning/ or missing ROADMAP.md both yield "No project").
    - Call `parseLite(content)` inside a separate try/catch. On success set `item.text = \`$(pulse) ${milestone} › ${phase}\``. On failure set `item.text = 'GSD: Parse error'` (locked decision).
    - The entire function must NEVER throw — outer activate() must not see a rejected promise crash the host.

    Implement `function parseLite(md: string): { milestone: string; phase: string }` — ≤40 lines:
    - Milestone derivation per planning context: prefer the first `## Milestone vX.Y` header if present; otherwise take the first H1 line (`^#\s+(.+)$` multiline) and strip a leading `Roadmap:\s*` prefix and a trailing `\s*—\s*Roadmap` suffix; if both yield nothing, fall back to the literal string `GSD`.
    - Active phase: scan lines in order. The first line matching `^###\s+Phase\s+\d+:\s+.+$` that does NOT contain `✅` and does NOT contain `[x]` (case-insensitive) wins. Capture the full text after `### ` (e.g., `Phase 1: Scaffold + Minimal Status Bar`).
    - If either milestone or phase cannot be derived (no H1 and no Milestone header → milestone defaults to `GSD`; no qualifying `### Phase` line → throw to trigger Parse error).
    - Trim both values before returning.
    - Use linear regex (no nested quantifiers) per RESEARCH security note V5.

    Strict-mode constraints (tsconfig has `strict: true`): no implicit `any`, no unused locals. Use `String#match` carefully (result may be null — narrow before indexing).

    After writing, run `npm run compile` and confirm `out/extension.js` is produced.

| ROADMAP.md content → regex parser | File content is treated as untrusted text (user-owned, but could be arbitrarily malformed) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-01 | Denial of Service | parseLite regex | mitigate | Use linear regex only (no nested quantifiers); active-phase scan iterates lines once. PARS-05 stress test arrives Phase 2. |

| T-01-02-04 | Information Disclosure | ROADMAP.md content rendering | accept | Status bar text is derived from a file the user already owns and can see; surfacing it back in the status bar is not a disclosure boundary |
