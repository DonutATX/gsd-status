# Phase 7 — UI Design Contract

> Visual and interaction contract for the Milestone-Collapsed Roadmap Support phase.
> Generated by gsd-ui-researcher. This is a VS Code extension phase —
> there is no web UI, no CSS, and no custom design system. VS Code's
> native theme governs all color, spacing, and typography.
>
> **Delta document.** Phase 5 UI-SPEC (`05-UI-SPEC.md`) is the baseline.
> This contract specifies only what changes from Phase 5. Everything not
> mentioned here remains identical to the Phase 5 contract.

---

## Design System

Unchanged from Phase 5. VS Code native theme governs all visual rendering.

| Property | Value |
|----------|-------|
| Tool | none (VS Code native theme) |
| Preset | not applicable |
| Component library | VS Code TreeView API (`vscode.TreeDataProvider<T>`, `vscode.TreeItem`) |
| Icon library | Codicons (`ThemeIcon` — built in to VS Code) |
| Font | VS Code editor font (user-controlled, not set by extension) |

Source: 07-CONTEXT.md `<decisions>` — no new UI libraries introduced.

## Spacing Scale

Unchanged from Phase 5. All spacing delegated to VS Code host theme.

The SVG icon asset remains 24×24px (no change).

## Typography

Unchanged from Phase 5. All text rendering delegated to VS Code host theme.

One new label category introduced:

| Role | Value |
|------|-------|
| Milestone node label | String assigned to `TreeItem.label` — VS Code renders at theme body size |
| Milestone node description | Optional string assigned to `TreeItem.description` — rendered as muted secondary text (e.g. phase range or shipped date) |

No custom font sizes or weights are set by this extension.

Unchanged from Phase 5. All color delegated to VS Code's active theme.

## Tree Node Hierarchy

### Full Structure (Phase 7)

This replaces the Phase 5 top-level structure. The "Recent Activity" section is
unchanged; the flat phase list becomes a milestone → phase hierarchy.

```
[Activity Bar] GSD icon
  └── GSD Panel (view id: gsd.treeView)
        ├── Recent Activity                          ← unchanged from Phase 5; always first
        │     ├── [entry 1]
        │     ├── [entry 2]
        │     └── ... (up to N entries, gsd.recentActivityCount)
        ├── v1.0 Milestone Name                      ← milestone node (active — expanded by default)
        │     ├── Phase 5: Side Panel TreeView       ← phase node (done)
        │     └── Phase 6: Packaging                 ← phase node (ACTIVE)
        ├── v2.0 Milestone Name                      ← milestone node (pending — collapsed)
        │     ├── Phase 7: ...                       ← phase node (pending)
        │     └── Phase 8: ...                       ← phase node (pending)
        └── ...
```

**Collapsed roadmap — range rows appear as-is from the Progress table:**

```
        ├── v1.0 Checklists & Callouts               ← milestone node (completed — collapsed)
        │     └── 1-4. v1.0 Checklists & Callouts    ← range phase node (archived, no children)
        ├── v1.1 Milestone Name                       ← milestone node (active — expanded)
        │     ├── 5. Phase Name                       ← phase node (done)
        │     └── 6. Phase Name                       ← phase node (ACTIVE)
```

**Single-milestone project (this repo — no `## Milestones` section):**

When no `## Milestones` section is present, fall back to the Phase 5 flat layout —
phase nodes remain top-level with no milestone wrapper.

Source: 07-CONTEXT.md `<decisions>` — "A roadmap with no `## Milestones` section at all falls back to today's flat phase list — backward compatible."

## Collapsible State Contract

Extends Phase 5 table with new milestone-specific rows:

| Node Type | Default State | Can User Collapse? |
|-----------|---------------|-------------------|
| "Recent Activity" section | Expanded | Yes |
| Milestone node (contains active phase) | Expanded | Yes |
| Milestone node (all phases done or pending, not active) | Collapsed | Yes |
| Active phase node | Expanded | Yes |
| Done phase node | Collapsed | Yes |
| Pending phase node | Collapsed | Yes |
| Archived/range phase node | Collapsed (leaf — no children) | No |
| Goal child item | Leaf (no children) | No |
| Success criterion child item | Leaf (no children) | No |
| Recent Activity entry | Leaf (no children) | No |

Source: 07-CONTEXT.md `<decisions>` — "The milestone containing the active phase is expanded by default; other milestones are collapsed."

## Interaction Contract

### Click Behaviors — Delta from Phase 5

| Node Type | On Click Action |
|-----------|----------------|
| Milestone node | No command (section header — expand/collapse only) |
| Archived/range phase node | Open `.planning/ROADMAP.md` via `vscode.window.showTextDocument` (no specific line — file open only, no `revealLine`) |
| All other nodes | Unchanged from Phase 5 |

Phase nodes that have a `headerLine` (expanded roadmap) continue to reveal that line.
Archived/range phase nodes have no `headerLine` (detail was archived), so they open
the file at the top.

Source: 07-CONTEXT.md `<decisions>` — "Phase nodes for collapsed/archived phases have no goal/criteria children ... the node simply has no children; never an error."

## Copywriting Contract

### New Labels (Phase 7 additions)

| Element | Copy |
|---------|------|
| Milestone node label | Milestone name verbatim from `## Milestones` bullets (e.g. `v1.0 Checklists & Callouts`) |
| Milestone node description | Phase range + shipped date if available (e.g. `Phases 1-4 · shipped 2026-03-21`); omit if not parseable |
| Archived range phase label | Row text verbatim from `## Progress` table (e.g. `1-4. v1.0 Checklists & Callouts`) |

### Unchanged Labels

All Phase 5 copywriting rules remain in effect:

- `Recent Activity` section header
- `Goal: ` prefix for goal child items
- `No recent activity` empty leaf
- `Error reading GSD files` error leaf
- Welcome view: `No GSD project found. Run /gsd:new-project to initialize.`
- Phase node labels verbatim from ROADMAP.md

### Copywriting Rules (additions)

- Milestone labels are used verbatim from the roadmap — do not add "Milestone:" prefix.
- Milestone description is optional; omit entirely rather than show a partial or malformed string.
- Range phase labels are used verbatim from the `## Progress` table row text.

Source: 07-CONTEXT.md `<decisions>` — milestone parsing from `## Milestones` section bullets.

## New Tree Item Type: `milestone`

The `GsdTreeItem` discriminated union in `src/tree/items.ts` gains a `milestone` variant.

| Property | Value |
|----------|-------|
| `kind` | `'milestone'` |
| `id` | `milestone-{slugified-name}` (e.g. `milestone-v1-0`) |
| `label` | Milestone name verbatim |
| `description` | Phase range + shipped date string, or `undefined` |
| `collapsibleState` | `TreeItemCollapsibleState.Expanded` (active) / `TreeItemCollapsibleState.Collapsed` (others) |
| `iconPath` | `new ThemeIcon('milestone')` or `new ThemeIcon('check-all')` for completed |
| `command` | `undefined` (no click action) |
| Children | Array of `GsdTreeItem` phase nodes belonging to this milestone |

Source: 07-CONTEXT.md `<code_context>` — "`src/tree/items.ts` — `GsdTreeItem` discriminated union; needs a new `milestone` variant."
